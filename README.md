# Parameterized_fifo_design_and_verification
Welcome! This project is a completely from-scratch implementation of a Parameterizable Synchronous FIFO written in Verilog.

A FIFO (First-In, First-Out) is one of the most fundamental building blocks in digital design, acting as an elastic buffer between a data producer and a data consumer. Instead of hardcoding a specific size, I designed this RTL to be fully parameterizable—meaning you can instantiate a tiny 8x4 buffer for control signals or a massive 64x1024 buffer for video pixels using the exact same verified module!

The entire design and verification flow was done using Xilinx Vivado.

** Key Features** : 
Highly Configurable: Both Data Width (DATA_WIDTH) and Depth (DEPTH) are exposed as parameters. The internal pointer widths automatically size themselves using $clog2() based on the depth you choose.
Native Hardware Wrapping: The internal pointers leverage absolute power-of-2 depth boundaries. This means no expensive comparators or multiplexers are used to wrap pointers back to zero; they naturally overflow in hardware, keeping the critical path incredibly short and fast.
The "MSB Trick": To flawlessly differentiate between "Full" and "Empty" states, the design uses an N+1 bit pointer architecture. The Most Significant Bit (MSB) tracks the physical wraparounds, allowing the combinational logic to predict the flag states safely in a single clock cycle.
Advanced Occupancy Flags: Features real-time fifo_count tracking that drives almost_full and almost_empty warning flags. These are critical for pipeline stalling in complex SoC data paths.

**Architecture Under the Hood** : 
If you look at the RTL, it boils down to four distinct blocks moving in harmony:

The Memory Array: A 2D register array that inherently infers into highly-efficient Block RAM (BRAM) during synthesis.
Write Logic: The "Producer." It looks at the incoming write-enables, ensures the memory isn't completely full, and latches the data.
Read Logic: The "Consumer." It looks at read-enables, ensures it isn't pulling from an empty buffer, and spits the data out.
Flag Computations: A purely combinational block acting as the "Referee." It constantly compares the Producer's pointer against the Consumer's pointer and immediately throws the full or empty flags to protect the data integrity.

** Verification Strategy (The Testbench)** :
Writing RTL is only half the battle. To guarantee this FIFO is bulletproof, I built a robust, self-checking verification environment:

Randomized Stimulus: The testbench doesn't just do basic linear writes and reads. It blasts the FIFO with heavy, randomized burst writes, randomized reads, and simultaneous read/write cycles to stress the flag logic boundary conditions.
The Scoreboard (Golden Reference): The testbench utilizes an internal software queue (the scoreboard). Every single piece of data written into the Verilog RTL is mirrored into the Scoreboard. As data is read out of the RTL, it is instantly compared against the expected Scoreboard data. If any mismatch occurs, the simulation halts and flags a data corruption error.

** Tools Used** :
Language: Verilog (RTL) & SystemVerilog/Verilog (Testbench)
Synthesis & Simulation: Xilinx Vivado

**How to Run (Simulation)** :
STEPS:-
Clone the repository.
Open Xilinx Vivado and create a new project.
Add sync_fifo.v as a Design Source.
Add tb_sync_fifo.v as a Simulation Source.
Hit Run Simulation -> Run Behavioral Simulation.
Check the Tcl Console for the [TEST PASSED] output generated by the Scoreboard!
